# VoiceLab v2 使用与验收

依据 `docs/designs/voice-lab-v2-product-preview.md` v0.3 实现。新界面与正式配音使用相同的 Speech Compiler 和 Runner；不再从旧 VoiceProfile 选择声音。

## 使用流程

1. 在「声音与素材」创建声音，添加实际引擎实现与普通／轻声／耳语来源。耳语版本必须绑定相应声音来源，不能用降低音量冒充。
2. 需要克隆时导入音频，查看波形、试听选段、填写并确认真实转录。可先识别台词，或分离人声后对比。素材复制到持久库，原文件不修改，也不会自动上传外部服务。
3. 创建明确的本地或远端连接，选择模型与模式，保存配方修订。本地连接可指定模型路径和设备；API 密钥不在配方、候选或任务快照中保存。
4. 在「台词与演绎」建立完整原文方案，逐句选择演绎和停顿。LLM 仅返回原文位置及意图，改写、遗漏、越界会被拒绝。检查请求不合成；生成候选会实际调用所选引擎。
5. 在「试音与对比」试听同一句的不同候选。等响度仅改变播放增益，不改音频文件。「采用配方」保存设置；「采用本句音频」选择真实片段，两者不同。
6. 在「用于配音」把配方送到工作台草稿，选择输入后手动提交。任务创建时固定配方与连接。正式配音实验也可逐句重生成、选择、重新组装并下载混音。

每次候选及配方修订均保留。组装保存采用关系和时长适配记录；未改变的候选不重新合成，时长适配文件可复用。超过字幕时段的声音以独立衍生产物适配，原始候选不覆盖。远端请求结果未知时阻止普通重试，需先核对服务端结果后再主动生成。

## 数据与旧资料导入

新资料默认位于 `config/voice_lab/`：公开元数据 `store.json`、参考素材 `assets/`、原始候选 `audio/`、时长适配 `aligned/`、组装 `assemblies/`。私密凭据单独存于 `credentials/`，不要分享整个资料目录。当前无自动删除未引用素材的流程，避免误删用户数据。

旧 `/voice/*`、`/tts/*` HTTP 入口及默认旧音色任务执行入口已退出运行链路。旧资料不自动导入、不删除；旧配音任务作为历史保留，不能用新引擎冒充原任务重试。

显式离线导入工具：

```powershell
.venv\Scripts\python.exe scripts/import_voice_library.py --help
.venv\Scripts\python.exe scripts/import_voice_library.py --voices <旧音色JSON路径> --connections config/config.json --connection-map <明确的连接映射JSON> --reference-map <已确认的参考转录JSON>
```

连接映射以旧 ID 为键，例如 `{"old-fish-id":{"provider_id":"fish_audio","deployment":"cloud"}}`，不根据 URL 推断协议。参考映射须提供已确认台词与语言。导入前备份输入及现有库，不能映射的数据保留并列入报告。导入练习应使用 `--root <独立测试目录>`。

## 验证范围

- 已通过五种真实本地合成：Qwen 预设、设计、参考；VoxCPM 设计、参考。均验证完整可解码输出，未将此等同于主观音质验收。
- Fish 与 OpenAI 兼容／MiMo 的协议、错误分类、取消及任务连接通过模拟服务测试；本轮没有调用付费云端接口。Fish 真实账户音色仍需用户配置后试听验收。
- 本地资源检测不加载模型。实际加载失败、限流、结果未知与音频解码失败会明确返回；不会静默切换引擎。
- 新 Provider 通过显式注册接入；通用界面读取配置 schema。没有任意插件安装、热加载或自动参考素材上传。
