# [已归档] 功能 9：结果预览、浏览与人工校对 V1 计划

## 目标

- 为任务结果提供统一的消费层能力，包括试听、查看、打开目录和轻量人工确认。
- 在不引入完整编辑器和复杂审核工作流的前提下，预留人工校对与人工确认环节。
- 避免将播放器、字幕查看、人工校对直接混入任务系统或结果资产层。

## 背景

- 当前仓库已经有底部播放器与任务结果展示的前端雏形，但其功能定位仍不稳定。
- 结果页未来可能会出现多种消费行为：
  - 试听音频
  - 查看字幕
  - 打开产物目录
  - 快速确认结果是否可接受
  - 人工标记需要返工或需要继续处理
- 这些行为与“结果资产是什么”不是同一层问题。
- 同时，完整人工校对工作流如果一次性展开，会带来明显的实现负担，不适合在当前阶段深挖。

## 功能定位

功能 9 是结果消费层。

它负责：

1. 基于功能 8 的结果资产做预览与浏览。
2. 提供最基础的试听和查看能力。
3. 提供轻量人工确认与校对入口。
4. 为后续更重的人工审核流预留扩展点。

它不负责结果生成，也不负责结果索引定义。

## 与其他功能的关系

### 与功能 8 的关系

- 功能 8 提供标准化结果资产与索引。
- 功能 9 只消费这些结果，不重新定义产物结构。

### 与功能 3 的关系

- 功能 3 负责任务状态。
- 功能 9 只在结果可消费时提供浏览与轻量确认。

### 与功能 2 / 4 / 7 的关系

- 功能 2、4、7 负责生产结果。
- 功能 9 不参与生产，只面向人工消费。

## 边界

### 本功能负责

- 音频试听入口
- 字幕查看入口
- 打开文件 / 打开目录入口
- 主产物优先展示逻辑
- 轻量人工确认状态
- 轻量人工备注或返工标记入口

### 本功能不负责

- 不负责重新定义 `Artifact` 结构，这属于功能 8
- 不负责真正修改字幕内容或音频内容
- 不负责复杂人工审核流程、多人协作审核、审校版本管理
- 不负责底层任务执行

## V1 需要实现的功能

### 1. 基础预览

V1 建议只确认这些基础能力：

- 试听主音频产物
- 查看字幕文本结果
- 从任务结果中快速打开文件或目录
- 查看任务主要 warnings 和失败信息

### 2. 结果浏览

V1 需要明确：

- 主产物优先展示
- 中间产物折叠或次级展示
- 失败任务仍可浏览已生成的部分结果

### 3. 轻量人工确认

这里可以加入人工校对环节，但先只定义为轻量状态，不展开复杂实现。

V1 可先预留：

- `accepted`
- `needs_review`
- `needs_rework`

说明：

- 这只是结果消费层的人工标记
- 不是完整审校流
- 不是字幕编辑器
- 不是任务重编排系统

### 4. 轻量人工备注

V1 可先允许：

- 对任务结果写简短备注
- 标记“这个结果需要重新跑”
- 标记“这个结果需要人工进一步处理”

但不要求：

- 多人协作评论
- 富文本批注
- cue 级逐条校对

## API 设计

V1 只需要轻量设计，不要求在这一轮完整展开。

### `GET /api/v1/tasks/{task_id}/preview`

用途：

- 返回适合预览层消费的摘要结果

### `POST /api/v1/tasks/{task_id}/review-status`

用途：

- 更新轻量人工确认状态

### `POST /api/v1/tasks/{task_id}/review-note`

用途：

- 保存简短人工备注

说明：

- 这些接口是消费层接口
- 不应反向主导任务执行与结果结构

## 中间层设计

### `PreviewService`

职责：

- 读取功能 8 的结果资产
- 组织预览层需要的最小摘要结构

### `ReviewMarkerService`

职责：

- 维护轻量人工确认状态
- 保存简短备注

## 与当前实现的关系

### 可以保留的思路

- 当前播放器和结果展示雏形可以继续保留
- 从任务结果中直接打开产物的方向是合理的

### 必须重组或警惕的部分

- 预览层不能反向定义结果模型
- 播放器不能替代结果资产层
- 人工校对不能在当前阶段膨胀成完整编辑器需求

### 明确不继承的历史包袱

- 不继承“播放器就是结果系统”的方式
- 不继承“人工校对一上来就等于复杂审校平台”的方式
- 不继承“页面想展示什么就自己拼结果结构”的方式

## V1 内必须落地

1. 基础试听与字幕查看入口
2. 打开文件 / 打开目录入口
3. 主产物优先展示逻辑
4. 轻量人工确认状态

## V1 内暂不落地

1. 不在这一轮做完整字幕编辑器
2. 不在这一轮做 cue 级人工校对流
3. 不在这一轮做多人审校协作
4. 不在这一轮做波形 AB 对比和片段循环系统

## 一句话结论

功能 9 可以正式定义为：

> 结果预览、浏览与人工校对 = 消费标准化结果资产，提供基础试听、查看、打开与轻量人工确认能力，但不在当前阶段展开成重型审核或编辑系统。
