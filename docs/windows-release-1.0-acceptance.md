# Windows 1.0.0 本地待验收包

1.0.0 功能和界面冻结。本轮只保存已批准源码、统一版本、构建安装包并检查隔离体验；不代表签名、公网发布或全新 Windows/VM 验收通过。

## beta 兼容策略

保留安装产品名 `ASMR Helper Test`、标识 `com.asmrhelper.desktop.test`、工作区标记 `.asmr-helper-workspace.json` 及其 `ASMRHelperTestWorkspace` schema identity。保留 `%LOCALAPPDATA%/ASMRHelperTest/workspace.json` 定位器和旧 `ASMRHelperTestData` 识别路径。已有有效工作区继续使用，配置、模型、输出、数据库和用户预设不自动移动或清空；新包的基础运行环境按 runtime identity 新建，旧基础环境不会自动删除。

系统应用列表仍显示 Test，当前文件是 1.0.0 待验收渠道。未经单独规划不改产品/工作区身份，避免另建产品后旧数据失联。源码 `RUNGUI.bat` 使用固定源码根；安装版使用所选独立工作区，数据库和 WebView 缓存均在该工作区中。

## 包体边界

只打包干净 CPython、锁定基础依赖、公开默认目录、当前应用源码、uv、FFmpeg 和第三方 notices。禁止开发 `.venv`、个人 config/凭据、声音库、数据库、缓存、音频产物或模型权重。FFmpeg 仍采用已记录 GPL v3 构建；第三方声明仅为支持材料，不是法律认证。

## 隔离安装前提

NSIS 的 `/D` 只改变安装位置，不隔离共享注册项；安装/卸载还可能结束当前用户同名 `asmr-helper.exe`。存在真实同名 NSIS/WiX 产品、启动项或正在运行的主程序时，不在该账户执行测试包，应使用独立 Windows 用户或 VM。保留用户正在运行的开发壳和工作区。

无冲突时，使用独立安装目录、空工作区、独立定位器。`/S /NS /D=<绝对目录>` 的 `/D` 必须为最后参数，不创建快捷方式、不自动启动。确认没有新增法律页及 WebView2 已存在；不得替用户接受新条款或安装共享运行时。

## 必须区分的验收项目

1. 构建/静态：版本锁一致、manifest/hash/CRC、无私密数据、notices 覆盖、安装器规则。
2. 真安装：独立目标安装成功；干净 PATH 下启动实际安装 exe，后端就绪，匿名 API 被拒绝，安装资源 hash 不变。
3. 原生首次体验：手动选择空工作区、确认资源准备、工作台“演示预设 · 中文配音”置顶并导入 `docs/examples/first-use.zh.srt`，使用 Edge 生成音频（无模型下载，需联网），检查任务和 WAV。
4. 重启：正常关闭后重开，工作区定位、预设、任务及输出保留，后端子进程清理。
5. 升级与卸载：仅在独立 Windows 用户/VM 或已确认无共享身份冲突的隔离目标做 beta→1.0 升级、重装和卸载。确认工作区保留；NSIS 卸载可能清理同标识跳转列表、启动项和注册信息，不能对真实产品试验。

提取安装包、启动独立 Python backend 或 API 脚本验证，均不能替代原生 GUI 首次体验。实际结果、包路径/大小/SHA256和未验收项记录在本次本地交付报告中；完成全部验收后才另行决定是否发布。
