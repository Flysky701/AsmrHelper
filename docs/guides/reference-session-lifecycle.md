# 声音库处理会话与页面切换

声音库的录音、未保存草稿、起止选区、字幕、分析任务标识、进度、结果与错误保存在 `referenceSessionStore` 中。侧栏页面卸载或声音与音色内部标签切换不会清空这些状态，也不会重新提交 ASR。

## 执行与恢复

- 后端沿用 `speech.reference_analyze` 与现有 TaskDispatcher。任务提交成功后独立执行，完成结果仍写入 `_analyses/<task_id>.json`。
- 前端会话分别跟踪整段分析与选段原文识别，每类只有一个状态观察器。轮询不依赖 React 页面是否挂载；页面仅订阅会话。
- 提交请求尚未返回时离开页面，也会记录随后返回的任务 ID。后台任务状态和原文识别结果随后更新到会话。
- 返回页面恢复当前录音和草稿。分段结果仍按时间排序，完整保留全部片段及引擎真实分数或“未提供置信度”。不会自动选用片段。
- 换成新录音会断开旧任务与当前草稿的关联。旧任务可继续在任务中心运行，其延迟响应不能写入新录音，即使重新导入的是同一路径。
- 选段识别完成时会比对音频、起止时间、语言和提交时的原文。期间有修改时保留结果供明确选用，不自动覆盖用户原文。
- 页面切换不再要求放弃声音库草稿；更换录音仍保留放弃当前草稿的确认。切页会暂停音频播放，后台分析继续。
- 连续状态查询失败会显示连接错误和重试入口；重试仅查询原任务，不再次执行 ASR。任务返回 404 时明确提示任务已不存在，不制造进度或自动提交新任务。

## 范围

恢复范围是同一次前端会话内的页面切换，不包含浏览器刷新、窗口退出或进程重启后的声音库草稿恢复；浏览器卸载时提示未保存草稿。后端已保存任务与结果按任务中心和恢复机制处理，重启后不自动重新关联声音库编辑草稿。
