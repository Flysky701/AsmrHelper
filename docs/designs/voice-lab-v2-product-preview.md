# 音色实验室 v2：完整目标与交互预览

> 历史设计记录：后续已调整为声音库、我的音色和试音记录三个独立入口；当前行为以 [使用说明](../guides/voice-lab-v2.md) 为准。本文中的流程和接口提案不代表全部现状。

状态：审阅草案 v0.3；2026-09-24。取代 v0.1 的兼容优先、分阶段产品范围；本次补充本地与外部 TTS 的扩展契约。以下接口为拟议设计，尚未实现。

## 1. 本轮约束调整

- 以完整新架构实现声音管理、参考素材、逐句演绎、候选对比、正式配音应用，不将旧 API、旧 JSON 或 Qwen 专属结构作为约束。
- 不保留旧接口适配器、双轨数据写入或长期兼容分支。新前后端成套切换；开发仍可分内部提交，但不把完整目标拆成多个不闭环的用户版本。
- 不兼容历史架构，不等于取消新引擎的扩展能力。新 Provider 契约是正式架构的一部分；后续引擎通过它接入，不要求修改声音库、候选管理和配音业务流程。
- 旧用户音频和配置不删除。提供一次性、显式的数据导入工具，导入前备份；它不参与新应用的运行路径。无法映射的数据留在原处并出具报告，不能假装导入成功。
- 本轮先交付可点击预览，供用户确认功能和流程；尚未运行真实合成，也未改动产品代码。

## 2. 可以直接感知的功能

| 功能 | 用户操作 | 应有结果 |
| --- | --- | --- |
| 声音库 | 创建声音，为其配置引擎实现 | 一个声音可有 Fish、本地参考等不同实现，显式选择默认实现 |
| 普通/耳语声音版本 | 给两个版本配置 Voice ID 或参考片段 | 切换声音来源，不伪装成调低音量 |
| 引擎专属设置 | 切换 Fish、VoxCPM、Qwen | 云端显示连接/Voice ID；本地显示参考素材或声音描述 |
| 参考素材整理 | 导入、看波形、选段、确认转录、比较原始/分离人声 | 形成持久、可追溯的声音参考，不依赖临时分析目录 |
| 演绎编辑 | 修改每句的发声风格、情绪、停顿 | 保持台词不变，按引擎能力转成实际请求 |
| 自动演绎 | 生成方案后人工修改 | LLM 只提供意图与位置，不改写台词、不自动选择付费引擎 |
| 多候选试音 | 重复生成、查看配置差异、等响度比较 | 每次结果保留；可选中满意候选，不覆盖历史 |
| 保存声音 | 保存当前引擎与演绎设置 | 新修订可复用，不污染已提交任务 |
| 用于正式配音 | 将候选配置送入 Workbench | 固定配置快照；后续逐句合成、对齐、混音、导出 |
| 局部重生成 | 只重做不满意的一句并选择新版本 | 未改片段保留，仅重算受影响的对齐和混音产物 |

“采用候选”分两种：实验室采用的是合成配方；正式任务逐句候选采用的是该段真实音频。界面必须区分，不能把试音句音频拼到不相关台词上。

## 3. 预览覆盖与限制

本轮交互预览提供四步：声音与素材、台词与演绎、试音与对比、用于配音。

可操作：选择引擎/模型、切换声音版本、修改试音文本和逐句风格/停顿、查看引擎文本示意、创建模拟候选、选定配置、转入工作台草稿、模拟单句重生成。

明确模拟：连接状态、参考素材、候选结果、自动演绎、保存和任务提交。不请求云端、不上传文件、不播放假音频、不产生音质分数或计费。

不在本轮预览实现的目标细节：真实波形裁剪、素材上传与持久化、真实音频 A/B、完整连接编辑、恢复和清理流程。不能以原型可点击代替后端实现完成。

示例 Voice ID 来自先前源码/实测记录，不意味着上游 ASMR 声音现在可访问，也不意味着两个示例声音保持同一说话人。

## 4. 新架构的唯一运行路径

```text
Voice Library（声音与参考资产）
       ↓
Speech Recipe（引擎绑定、声音版本、演绎配置）
       ↓
Speech Plan（固定原文、分句、意图和停顿）
       ↓
Speech Compiler（能力校验、引擎特化、不可变请求）
       ↓
Synthesis Runner（现有任务基础设施、取消、缓存、产物）
       ↓
Provider（Fish / Qwen / VoxCPM / Edge / OpenAI compatible）
       ↓
Segment Take（每段多个真实候选与采用版本）
       ↓
Assembly（现有对齐与混音功能，通过新契约接入）
```

实验室和 Workbench 使用同一 Compiler/Runner。保留有价值的任务、音频工具和运行时隔离实现，不保留它们不合适的旧接口。重构不等于重写已验证的底层推理算法。

### 4.1 一组规范对象

- **Voice**：用户理解的声音身份，包含名称、描述和多个 provider binding；不包含人物剧情。
- **VoiceVariant**：normal/soft/whisper 的声音来源；来源可为 hosted ID、builtin speaker、reference asset 或 design description。
- **ReferenceAsset**：持久音频、真实转录、语言、切片来源、摘要及处理版本。
- **SpeechRecipe**：绑定 provider/model/connection、variant 和默认演绎；每次保存产生不可变 revision。
- **SpeechPlan**：原文及稳定 segment_id、演绎意图、停顿；LLM 计划只是一个来源，人工编辑同样有效。
- **CompiledRequest**：解析后的实际模型/声音/标签/参数、映射警告、编译器版本；不含密钥。
- **Experiment**：公共试音文本与候选集合。
- **SegmentTake**：task_id、compiled request、音频 artifact、状态来源和耗时；不可变。
- **TakeSelection / AssemblyRevision**：采用哪段音频及其组装版本，避免把“选用”写进任务终态。

旧 VoiceProfile 不作为新模型的父类。Qwen prompt 是由 reference、模型与参数派生的引擎缓存，不是跨引擎声音身份。

### 4.2 Provider 接口应具有的职责

提供能力描述、输入校验、合成和取消响应边界。模型模式不同可返回不同能力。Fish renderer 生成标签和请求参数；Qwen 根据设计/克隆模式选择输入；VoxCPM 使用参考材料。不要在统一 interface 中强制所有模型接受 instructions。

支持程度区分 direct（原生参数）、reference（参考引导）、postprocess（如句后静音）、unsupported；同时单独记录实测状态。无法满足意图时先报缺失配置或要求用户选择回退，不静默丢弃。

所有 Provider 输出可解码音频与一致元数据，由 Artifact 服务登记。试音保留原始输出；正式输出的时长适配记录单独处理步骤。

### 4.3 Fish 专属边界

独立 `fish_audio` Provider，连接类型明确；模型放正确 header、声音 ID、自由描述标签、标签密度和高级参数均由 Fish 模块处理。

Fish 参数随 API/模型验证，不能直接承诺上游全部 prosody 字段生效。temperature 与情绪强度分离。语音规划器输出语义意图，不能直接输出一段仅 Fish 认识的字符串作为通用计划。

### 4.4 本地与外部引擎的接入边界

Provider 表示引擎协议与行为，Connection 表示某次部署的运行位置和连接配置，两者不能混为一谈。同一引擎可以连接本机服务、局域网服务或云端服务；不能仅凭地址推断协议和能力。

| 层次 | 职责 | 新增引擎时的变更 |
| --- | --- | --- |
| 声音库、Recipe、Plan、候选与配音界面 | 管理用户意图和结果 | 复用，不按引擎复制页面 |
| Provider 注册表与描述 | 声明模型模式、配置结构、能力及版本 | 注册新模块 |
| Provider 编译器 | 验证输入，将意图映射为引擎请求 | 实现特有映射和校验 |
| Provider 执行器 | 本地推理或远端调用，解析结果 | 实现执行和资源释放 |
| Runner 与 Artifact | 任务、取消信号、产物登记、候选归属 | 复用公共机制 |
| 可选专属配置组件 | 通用表单无法表达的特殊操作 | 仅扩展对应配置区 |

普通字符串、枚举、数值及范围由配置 schema 驱动表单。特殊声音设计、云端音色选择等使用已注册的前端组件，不下载服务端提供的可执行界面代码。后端仍是配置校验的权威，不能只靠隐藏控件阻止无效请求。

首版使用随应用发布的显式模块注册，不引入任意插件安装或热加载系统。协议兼容的服务可复用已有 Provider；独有协议和推理方式需要开发新 Provider，不能承诺填写任意 URL 即可接入。

### 4.5 拟议 Provider 契约

下列名称表示职责，最终语言签名在实现前冻结：

| 操作 | 输入与输出 | 约束 |
| --- | --- | --- |
| `describe` | 返回 provider_id、契约版本、配置 schema、支持的运行方式 | 无密钥、无模型加载副作用 |
| `probe` | 连接引用 → 可达性、依赖/模型就绪状态 | 不合成、不自动下载模型；结果与“听感有效”分开 |
| `capabilities` | 模型、模式、部署信息 → 能力描述 | 未知能力标为未验证，不默认支持 |
| `validate / compile` | Recipe、Plan、资产描述 → 不可变 CompiledRequest 或结构化问题 | 不发送音频、不收费；不包含密钥 |
| `synthesize` | 已编译请求、运行上下文、取消信号 → 音频结果或事件流 | 执行上下文临时解析凭据；结果由 Runner 登记 |
| `release` | 运行资源句柄 → 清理完成 | 释放模型/进程/连接，不删除用户资产 |

运行资源准备由执行阶段显式处理；需要模型下载或参考音频上传时，以独立、可见的准备操作完成，不能藏在能力查询中。声音枚举、声音创建、流式合成是可选能力，无能力时不要求实现空接口。

音频结果至少包含容器/编码、采样率、声道、时长、实际模型信息和远端请求 ID（若有）。流式事件包含有序序号、格式与完成/失败标记；只有完整且可解码的最终产物能成为可采用候选。流式支持不代表时长对齐与混音也能流式执行。

能力描述按模型与模式细分：语言、声音来源类型、参考素材限制、文本长度限制、情绪/发声控制、停顿、流式、并发和取消边界。每项同时表达支持方式（direct/reference/postprocess/unsupported）与证据状态（未验证/已实测及版本），不把“服务接受参数”当成“耳语效果已验证”。

### 4.6 配置、缓存与失败行为

- **共享字段**：provider_id、model/mode、connection_ref、voice_variant_ref、语言与公共演绎意图。**专属字段**：放入带 schema_version 的 provider_options，由对应模块验证；禁止任意透传未知字段。Fish 标签、温度与请求头不进入通用领域对象。
- **本地运行**：配置模型路径、设备、精度和隔离环境；由资源调度限制模型驻留和并发，避免多个任务同时加载导致显存耗尽。进程是否可抢占由 Provider 声明，不能以取消 UI 假装已终止 GPU 推理。
- **外部服务**：配置地址、凭据引用、超时和并发限制；区分认证失败、限流、连接失败、模型不可用和响应不可解码。请求可能已受理但响应超时时标为结果未知，未经确认不能自动重复付费生成；仅在确认安全或服务支持幂等时重试。
- **资产边界**：参考音频长期保存为本地资产；服务需要上传时记录目标连接、资产摘要和返回的远端引用。不同连接不能共享其私有引用。默认不为更换引擎自动上传已有素材。
- **快照与恢复**：编译结果固定 Provider/编译器/schema 版本、模型身份、素材摘要、演绎及有效参数；凭据独立存储。连接编辑不能改变已提交任务的目标；恢复时若凭据不可用或引擎版本不匹配，明确阻断或创建新任务，不悄悄切换。
- **缓存与候选**：缓存键覆盖上述影响输出的字段、seed（支持时）及处理版本；缓存命中可复用已有结果，但用户“生成新候选”显式绕过结果缓存，避免随机试音总返回同一音频。无法固定的远端模型版本注明可复现限制。
- **降级**：不支持的意图在编译阶段返回具体原因及可选处理；用户明确选定后生成新计划修订。不静默丢弃标签、切换音色、转云端或退回旧引擎。

### 4.7 新增引擎的交付清单

1. 声明 Provider ID、配置 schema、运行方式、模型模式和能力；给出专属参数与声音来源的映射。
2. 实现校验、编译、执行与释放；复用公共任务、凭据、资产和产物设施。
3. 注册配置表单；只有通用表单不足时新增专属组件。
4. 通过契约测试：无效配置、缺失参考、不支持意图、取消、错误分类、输出格式及快照隔离。
5. 完成真实端到端验收：实验室生成并比较 → 保存配方 → 正式配音 → 单句重生成 → 导出；另行记录中文可懂度、声线一致性与风格听感，不能只验证 HTTP 成功。

以一个额外的本地测试 Provider 和一个模拟远端 Provider 验证扩展边界：无需修改实验室/Workbench 的业务分支即可完成契约流程。模拟服务负责稳定测试限流、超时和断流；不能代替真实引擎的声音验收。

## 5. 完整替换的切换策略

1. 冻结新领域对象、任务 payload、API 和前端类型；为新 Compiler/Runner 建立契约测试。
2. 完成所有当前正式支持引擎的 adapter，迁移实验室和 Workbench 到新链路；旧代码只在开发期间存在，不能成为新运行路径的回退。
3. 完成候选、参考素材、自动演绎、单句采用和组装版本管理。
4. 执行一次性导入演练、全链路回归与真实声音验收；完成后成套替换旧入口、路由、配置读写及测试。
5. 发布时只保留新路径与离线导入工具；源数据备份用于回滚，应用内不做新旧混合运行。

数据导入：旧 A/B/C 音色转换为 Voice+Qwen binding；引用音频保留来源摘要，旧 prompt 仅在能确认匹配时作为缓存导入，否则重建。旧连接导入后明确 provider，不按 URL 猜类型。旧任务作为只读历史保留，不能以新逻辑冒充原运行重试。

完整替换的范围包含音色实验室与其正式 TTS 接线，**不扩大到重写 ASR、翻译、全部任务系统或混音算法**。

## 6. 验收必须看到的行为

- Fish 声音可以从配置、试音、保存到正式混音导出跑通。
- Qwen/VoxCPM 参考路径和原有正式支持引擎在新接口下可用，没有旧入口兜底。
- 更换引擎后不支持的控制不会假装有效；参考缺失有明确阻断。
- 改台词/参数只创建新候选；采用某句的新候选只使相关组装结果失效。
- LLM 自动演绎无法改写、漏掉、新增台词；计划失败的行为可见。
- 创建任务后编辑声音/连接不污染任务；密钥不进入候选记录。
- 取消不再生成后续片段；远端超时不无条件重复收费请求。
- 同一 compiled request 在实验室与正式合成阶段映射一致；对齐改变听感时可追溯。
- 预设保存、候选选择和导入均可验证持久化；未引用文件清理不误删来源或已采用片段。
- 新增本地/外部 Provider 仅变更注册、引擎模块和必要的配置组件，不复制声音库、候选或配音业务逻辑。
- 协议兼容服务复用连接器前通过能力和输出契约测试；切换模型模式后配置重新校验，不沿用失效能力。
- 本地资源不足、远端限流/结果未知、流式中断都有可验证的状态；不把不完整音频标为成功候选。

## 7. 本次希望从预览得到的反馈

优先判断：声音与演绎是否需要四步分开；引擎专属项是否清晰；候选到正式配音的动作是否符合预期；是否需要更突出逐句编辑，而弱化声音库。

听感强弱仍需真实模型验证。架构完整可交付，不意味着能够保证任意音色都变成自然耳语。
