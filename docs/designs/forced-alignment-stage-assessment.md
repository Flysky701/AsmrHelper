# 字幕时间轴对齐阶段评估（草案）

日期：2026-09-23。用户目标：原音频与识别结果或台本文字对齐，修正字幕时间轴。本文件是评估，不表示新阶段已经实现，也不包含配音时长调整。

## 结论与流程

建议将 Qwen3-ForcedAligner-0.6B 作为独立、可选的 `align` 阶段：

`原音频 → 可选人声分离 → ASR → 字幕对齐 → 翻译 → TTS → 混音 / 导出`

短音频且已有匹配的逐字台本时，可跳过 ASR，输入音频、文字和语言直接对齐。长台本没有时间锚点时，仍需粗识别或其他可靠的音文分块匹配，不能只按字符数量把文本平均分给音频。

## 项目已有基础

- `config/models.yaml` 已登记 `qwen3-forced-aligner-0.6b`，目前归为 Qwen3-ASR 的附属资产，使用 `qwen_asr` 隔离运行时。
- `src/core/engines/asr/service.py` 会在 Qwen3-ASR 请求时间戳时传入该模型；`qwen3_asr.py` 已有时间戳归一化、句子聚合和对齐分块设置。
- Pipeline 的阶段模型、执行器和前端阶段清单尚无独立 alignment 阶段；其他 ASR 结果无法通过此阶段统一校准。
- 台本转字幕当前经过清洗、Faster-Whisper、LLM 文本重排。强制对齐应在选定最终原文之后校准时间，文本匹配与声学时间定位各自负责不同工作。
- 本次目录检查未见 `models/qwen3asr/Qwen3-ForcedAligner-0.6B`；未重新做模型安装、加载或推理。

## 建议边界

1. 输入：音频路径、同语言原文、语言和可选粗时间锚点。首次实现复用 ASR 段落；带时间轴且准确的字幕默认不重复对齐。
2. 输出：词/字时间戳 JSON 与句级字幕；保留原稿和原时间轴，导出对齐后的 SRT/VTT。不要覆盖用户源文件。
3. 主流程显示一个“校准字幕时间轴”开关。用户选择启用而资源不足时给出明确安装提示，不静默跳过。已有 Qwen 内部对齐结果时避免重复推理，记录是否复用。
4. 对齐后的分句须发生在翻译前，避免译文与原文段落错位。字幕工坊提供独立“音频 + 文稿 → 对齐字幕”任务，复用同一执行服务。
5. Worker 在已有 `qwen_asr` 环境直接加载 `Qwen3ForcedAligner`；不为单独对齐额外加载 Qwen ASR 模型。ASR、对齐和 TTS 顺序释放显存。
6. 不假设模型提供可靠置信度：先使用越界、倒序、零时长、异常跨度等可解释检查，异常片段保留原始数据并标记待检查。

## 难点与验收

- 官方描述的单次支持范围为不超过五分钟音频；长 ASMR 必须分块，并将块内秒数准确转换为整轨时间。已有粗时间戳只用于定位窗口，不锁死新边界。
- 低声耳语、长静音、呼吸音、重复词、漏读和台本旁白是重点样本；模型不能替代识别纠错，也不能把不同内容强行对齐。
- 日语分词和长音频分块需要使用实际依赖及模型文档核对，不将 ASR 的语言列表直接当作对齐模型语言列表。
- 需要联动调整 Pipeline profile / planner / executor、任务阶段进度与错误、readiness、模型资源关联、产物索引、前端阶段展示与字幕任务。
- 测试覆盖：ASR 原文、准确台本、长文件块偏移、分块边界、重复语句、缺字/多字、零时长、取消和缺模型；实测对比校准前后字幕边界，记录耗时与峰值显存后再决定是否默认开启。

实施建议：先完成独立对齐服务和短音频任务，再接入 ASR 后的可选阶段，最后完善长台本匹配。整体为中等范围功能，主要工作在长音频与字幕数据衔接，而非模型调用本身。

依据：[官方模型卡](https://huggingface.co/Qwen/Qwen3-ForcedAligner-0.6B)、[官方独立调用示例](https://github.com/QwenLM/Qwen3-ASR/blob/main/examples/example_qwen3_forced_aligner.py)，以及项目当前源码与本机已安装的 `qwen_asr/inference/qwen3_forced_aligner.py`。
