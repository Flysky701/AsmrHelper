# 前端 localhost 连接问题修复计划

## 目标

- 修复当前桌面前端与本地后端之间的连接地址不一致问题。
- 让前端在连接失败时给出更明确的错误语义，降低排查成本。

## 背景

- 后端入口默认绑定 `127.0.0.1:8000`。
- `GUIRun.bat` 的健康检查和后端启动也已经统一使用 `127.0.0.1:8000`。
- 但前端 `desktop/src/api/client.ts` 仍写死 `http://localhost:8000/api/v1`。
- 虽然当前机器上 `localhost` 也能访问，但这条链路与脚本、后端绑定地址并不一致，仍然容易在不同环境里表现为“前端无法连接到 localhost”。

## 步骤

1. 将前端默认 API 基址改为 `http://127.0.0.1:8000/api/v1`。
2. 支持通过 `VITE_API_BASE` 覆盖默认地址，便于 dev 场景调整。
3. 在网络请求失败时抛出明确的 `NETWORK_ERROR`，直接带出目标基址。
4. 将 `GUIRun.bat` 的 dev 启动也显式注入 `VITE_API_BASE`。
5. 重新验证前端构建。

## 验证

- 前端构建通过。
- 代码层前端、脚本层后端、健康检查地址统一使用 `127.0.0.1:8000`。

## 风险

- 本轮修复的是地址一致性与错误可观测性，不涉及页面业务逻辑。
- 若未来需要远程后端或非默认端口，仍需要通过环境变量或配置继续扩展。
