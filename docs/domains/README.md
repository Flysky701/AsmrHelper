# 领域边界

> 本目录只保留当前责任边界。跨进程字段、API 和 Provider 参数分别以 `docs/contracts` 下的 v1 契约为准。

## 1. 输入与执行上下文

负责输入文件、伴随资产、输出位置和一次执行所需的上下文。Workspace、Input、Session 可以作为后端高级资源存在，但 Workbench 默认流程不负责逐级编排它们。

不负责任务排队、工具调用和 Provider 凭据解析。

## 2. 任务与队列

负责任务创建、状态事实、进度、取消、重试和后台调度。任务状态是桌面端展示的唯一事实源。终态历史持久化；重启时未完成任务被清理，不恢复执行。

不负责解释具体媒体算法，也不从前端显示状态反推执行状态。

## 3. Pipeline 与工具执行

负责固定阶段顺序、阶段输入输出衔接、工具调用和阶段错误归属。当前主链路不是任意 DAG。

不保存全局设置，不向桌面端暴露命令行细节。

## 4. Provider 与运行时资源

负责 ASR、TTS、翻译、分离和媒体 Provider 的注册、能力描述、参数适配、凭据解析、模型资源与依赖检查。

ASR、TTS、LLM 是 Provider 类别，不再分别维护一套重复的领域契约。

## 5. 字幕与文本资产

负责字幕段、语言、时间轴、翻译文本和编辑后的文本资产。内部可以保留可追溯版本，但主链路只交换标准资产引用。

不负责直接驱动外部 LLM 或 TTS SDK。

## 6. 产物与预览

负责登记阶段产物、确定主产物、提供预览所需元数据和结果索引。桌面端通过产物接口获取结果，不按文件名或目录规则猜测。

不负责 Pipeline 调度或重跑策略。
