# 长任务阶段恢复：范围与验收

日期：2026-09-23。用户已批准实施。本文描述批准的范围、设计边界与验收要求，不作为全部能力已完成或已验证的证明；实际完成情况以实现与测试结果为准。

## 范围

为 Pipeline 添加阶段级检查点与重启后的显式继续。已完成且通过校验的阶段可以复用；中断、失败或检查点无效的阶段整体重新执行。覆盖分离、识别、对齐、翻译、语音合成、混音及导出中实际启用的阶段。

**恢复粒度固定为整个阶段。不实现阶段内分块、逐句或翻译批次恢复，也不将这些能力列为后续待办。** 不保存模型内存、GPU 上下文或供应商内部生成进度。此项范围不扩展至模型下载、音色克隆等独立工具任务。

例如识别成功、翻译执行中退出：重启后由用户点击“继续处理”，校验通过则复用识别结果，整个翻译阶段重新执行。TTS 执行中退出时，整个 TTS 阶段重新执行，不复用该阶段尚未提交的句段。

## 原有缺口

- SQLite 已保存任务历史，但原有启动逻辑删除非终态任务，历史任务无法继续。
- Pipeline 依赖内存中的 Session/InputAsset；仅保存任务 ID 无法重建执行输入。
- skip_existing 主要检查文件存在，无法证明成功、完整性或配置一致。
- 若阶段捕获异常后回退并记录 step_errors，不能将返回值视作成功检查点。
- 服务配置可以切换；恢复不能静默采用后来选中的提供商、模型或凭据。

## 持久化契约

### 执行清单

保存版本化执行清单，包含原音频与伴随字幕路径、内容身份、源/目标语言、解析后的阶段配置、输出策略和重建执行上下文所需字段。清单应足以脱离原进程的 Session/InputAsset 索引恢复任务。

服务连接保存稳定档案 ID、非敏感配置快照及核验信息。API Key 不进入任务公开信息或恢复数据库。恢复时通过原档案引用解析凭据；原连接不可用或配置不匹配时给出明确阻塞原因，不回退到当前全局默认连接。

### 成功检查点

每个检查点记录版本、阶段名、阶段指纹、结构化结果、完整产物清单、内容 hash、文件大小、成功时间和生产任务 ID。ASR/对齐保留时间戳与文本结构，翻译保留与段落的对应关系；不能仅通过展示用 TXT 推断阶段结果。

阶段成功后先保存独立的完整产物副本，再提交 SQLite 检查点事实。数据库记录提交前的文件不属于可恢复成果；写入或提交失败不得替换之前有效的检查点。新的尝试不能覆盖历史检查点文件。

恢复必须核验文件存在、大小与内容 hash，结合阶段结果结构判断能否使用。空产物、缺失产物、损坏产物和携带阶段错误的结果不能充当成功事实。仅有路径、相同文件名或进度百分比不足以证明完成。

### 中断与历史

启动时保留具有执行清单的未完成任务，记录明确的中断原因，不自动发起模型调用。可以沿用失败终态并通过 TASK_INTERRUPTED 区分中断，无需虚构执行完成。

显式继续创建新任务尝试，保留来源关系与原始历史。原任务的错误、时间和产物来源可追溯。缺少执行清单的旧任务明确不可继续，不能伪造恢复资格。

每次尝试使用独立输出位置，避免原执行者或失败尝试覆盖可复用成果。继续请求需防止同一来源被重复提交并发运行；任务排队、取消及实际执行仍由现有调度器负责。

## 失效规则

阶段指纹包含影响该阶段结果的输入、配置、模型身份和上游依赖。恢复使用原配置快照；如果运行所需身份改变，不能盲目复用结果。允许保守地扩大失效范围，但不能错误复用受影响的下游。

| 变化 | 至少必须失效的范围 |
| --- | --- |
| 原音频内容变化 | 依赖原音频的阶段及下游 |
| ASR 模型、语言或识别参数变化 | ASR 及下游 |
| 对齐台本、模型或时间轴处理配置变化 | 对齐及依赖其输出的下游 |
| 翻译模型、端点、提示词或术语变化 | 翻译及下游 |
| TTS 模型、音色或合成参数变化 | TTS 及下游 |
| 混音或导出配置变化 | 对应阶段及下游 |
| 检查点产物被删除或改写 | 对应阶段及下游 |

模型身份应使用可取得的版本或权重身份信息。仅有可变远端模型别名时，不能宣称能检测供应商内部所有变化。凭据轮换或连接档案变更需要重新核验原连接，不得自动借用其他档案。

## 用户操作与接口

- GET /tasks/{id}/recovery：返回是否可继续、阻塞原因及可复用阶段信息。
- POST /tasks/{id}/resume：再次校验并创建继续任务，返回新任务状态。
- 任务中心提供“继续处理”，解释已经保留的阶段；不可继续时说明原因。
- 取消保留已提交检查点；继续必须由用户显式触发。中断阶段整体重新运行。
- 原有重新提交能力与继续入口区分清楚；重新创建任务不意味着已经复用检查点。

外部调用在中断前可能已经由供应商执行。缺少供应商幂等或结果查询保证时，阶段重跑可能重新发起请求；不能承诺外部请求恰好执行一次。

## 验收要求

1. 保存执行清单后重启，仍可识别可恢复任务并重建上下文；不依赖旧进程内存对象。
2. 已成功提交的阶段通过验证后不再次调用；中断阶段从阶段起点整体执行。
3. 产物复制失败、空产物或 SQLite 提交失败时，不发布新成功检查点，不损坏旧有效检查点。
4. 删除、截断或等长改写检查点文件，内容验证能发现异常；不能把文件存在当成功。
5. 输入、配置、模型或上游发生变化时，拒绝错误复用受影响结果。
6. 服务档案切换后仍解析原连接，缺失或不匹配时阻止继续；任务公开响应与数据库无明文密钥。
7. 中断任务保留错误原因、进度和原时间信息；终态历史不被启动逻辑改写；新旧尝试关系可追溯。
8. 重复继续不产生同源并发执行；取消或重启不自动启动外部调用。
9. 对齐阶段保存原始段落、对齐结果与字幕产物，恢复后的时间轴与首次成功执行一致。

此能力的关键是可靠的成功事实、完整执行输入和失效规则。持久化存储单元测试不能代替完整流水线、API、连接配置和实际中断路径的集成验收。
