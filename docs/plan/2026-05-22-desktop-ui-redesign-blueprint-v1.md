# Desktop UI Redesign Blueprint v1

日期：2026-05-22

范围：仅覆盖 `desktop/` 新桌面端。旧 GUI `src/gui/` 暂不调整，待新 GUI 验证成功后再考虑删除。

## 1. 当前判断

当前 desktop 前端已经具备基本任务入口、参数配置、任务列表和日志查看能力，但界面仍像“功能表单拼接”，还没有形成适合音频流水线工作的生产台。

主要问题不是单个按钮形状，而是信息层级、任务路径和反馈机制不够清晰：

- Workbench 的主线不明显：用户看到的是文件、预设、参数、高级选项和执行按钮，但不容易理解“我正在配置一条什么流水线”。
- 主操作位置偏弱：执行按钮在页面底部，和文件选择、预设选择、任务结果之间的关系不够紧。
- 参数暴露过多：普通用户一进入页面就看到大量模型、音量、延迟、语速选项，容易产生配置负担。
- TaskCenter 更像日志列表：任务卡片能显示状态，但没有强调当前阶段、下一步操作和产物入口。
- 日志权重过高：日志对调试有价值，但对普通使用者来说不是主要结果，应降级到详情区。
- 视觉系统偏灰、偏软：当前 neumorphism 风格容易显得像 Demo，长期使用时层级和可扫读性不足。
- 中文文案存在乱码风险：当前页面源码中已有乱码文案，设计落地前必须先恢复可读文案，否则按钮和字段语义无法被可靠评审。

## 2. 设计目标

新界面应该让用户感觉自己在操作一个“音频生产工作台”，而不是填写一张参数表。

核心目标：

- 用户 5 秒内知道下一步该做什么。
- 用户能看懂任务会经历哪些阶段。
- 用户能在任务运行时知道它卡在哪一步。
- 用户能在任务完成后直接找到结果产物。
- 高级参数存在，但不抢占主流程。
- 日志存在，但默认服务于排障，不作为主界面中心。

## 3. 推荐视觉方向

推荐方向：Light Production Desk。

关键词：

- 浅色、干净、专业。
- 更接近音频工作台和生产控制台，而不是传统后台管理系统。
- 用清晰边界、细线、状态色和流程节点建立层级。
- 少用厚重拟物阴影，避免整页灰色软卡片。
- 圆角控制在 8-12px，减少层层套卡。
- 使用更明确的主色，例如低饱和蓝绿或墨蓝，不继续依赖浅蓝灰 neumorphism。

建议 token 方向：

- 背景：接近白色或极浅冷灰，而不是整页中灰。
- 主面板：白色或轻微蓝灰 tint。
- 边框：细线 `#d7dee8` 一类，替代大面积阴影。
- 主操作色：沉稳蓝绿或专业蓝，例如 `#236f7e` / `#1f6feb` 二选一。
- 成功/失败/警告：语义色清晰，但避免过亮。
- 字体：中文优先保证清晰，建议保留系统中文栈，但重设字号、字重、行高。

## 4. Workbench 新结构

Workbench 应从“配置表单”改成“任务创建工作台”。

推荐布局：

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部任务带：选择文件 / 选择预设 / 创建并执行                  │
├──────────────────────────────────────┬───────────────────────┤
│ 主工作区                              │ 右侧摘要区             │
│                                      │                       │
│ 1. 文件队列                           │ 当前预设               │
│ 2. 流水线阶段                         │ 参数摘要               │
│    分离 -> ASR -> 翻译 -> TTS -> 混音  │ 预计输出               │
│ 3. 关键参数                           │ 最近任务               │
│                                      │                       │
└──────────────────────────────────────┴───────────────────────┘
```

### 顶部任务带

顶部应该承载最核心动作：

- `添加音频`：主输入入口。
- `预设`：和文件选择同一层级，因为它决定默认流水线。
- `创建并执行`：主按钮固定在任务带右侧，而不是页面底部。

按钮设计建议：

- 主按钮只保留一个：`创建并执行`。
- 次级按钮：`添加音频`、`清空列表`。
- 危险按钮：删除文件、取消任务。
- 不建议所有按钮都用同一种凸起形状，应通过 primary / secondary / ghost / danger 区分。

### 文件队列

文件列表应成为任务创建的第一主角：

- 空状态显示清楚的拖拽/选择提示。
- 已选文件以行列表展示，不建议用大卡片堆叠。
- 每行显示文件名、路径缩略、预计处理类型、删除按钮。
- 多文件时显示总数，例如 `已选择 5 个音频`。

### 流水线阶段

增加可视化流程条：

```text
人声分离 -> 语音识别 -> 字幕翻译 -> 语音合成 -> 混音输出
```

每个阶段显示：

- 是否启用。
- 使用的模型/服务简写。
- 当前配置是否完整。

这比把所有参数平铺出来更容易理解。

### 参数区

参数分两层：

- 常用参数：源语言、目标语言、TTS 引擎、ASR 模型、是否人声分离。
- 高级参数：音量比例、延迟、语速、跳过已有输出、voice profile。

常用参数可以直接展示。高级参数默认折叠，建议改为右侧抽屉或局部展开，不要占据主流程空间。

### 右侧摘要区

右侧不是日志区，而是“执行前确认”：

- 当前预设。
- 输入数量。
- 目标语言。
- TTS 引擎。
- 预计输出类型。
- 最近 3 个任务。

用户点击执行前，应能在这里确认“这次会发生什么”。

## 5. TaskCenter 新结构

TaskCenter 应从“任务列表 + 日志”改为“任务驾驶舱”。

推荐布局：

```text
┌──────────────────────────────────────────────────────────────┐
│ 筛选 + 批量操作                                                │
├──────────────────────────────────────┬───────────────────────┤
│ 任务列表                              │ 任务详情               │
│                                      │                       │
│ 任务卡片：                            │ 当前阶段               │
│ 文件名 / 状态 / 进度 / 当前阶段        │ 产物入口               │
│ 完成后展示主要产物操作                 │ 参数快照               │
│                                      │ 日志折叠区             │
└──────────────────────────────────────┴───────────────────────┘
```

### 任务卡片

任务卡片应优先显示用户关心的信息：

- 文件名。
- 状态。
- 当前阶段，例如 `正在翻译字幕`。
- 进度条。
- 失败原因摘要。
- 完成后的主要产物按钮。

完成任务的主要动作建议：

- `播放混音`
- `打开字幕`
- `查看输出`
- `重新执行`

日志不应该出现在每张卡片的主视觉里。

### 任务详情

右侧详情建议显示：

- 当前阶段。
- 阶段时间线。
- 输出产物。
- 参数快照。
- 日志折叠面板。

日志筛选仍然保留，但默认放在详情底部，用户需要排障时再展开。

## 6. 组件规范

建议先定义这些基础组件，再改页面：

- `Button`：primary / secondary / ghost / danger / icon。
- `Panel`：页面主面板，不再叫 NeuCard。
- `FileQueueRow`：文件队列行。
- `PipelineStep`：流水线阶段节点。
- `ParameterSummary`：参数摘要。
- `TaskCard`：任务卡片。
- `ArtifactBar`：结果产物操作条。
- `StatusPill`：状态标签。
- `LogDrawer`：日志详情区。

不建议继续用 `Neu*` 作为长期组件命名。可以兼容过渡，但新设计系统应逐步摆脱 neumorphism 命名。

## 7. Figma 建议画板

如果 Figma 工具接口可用，建议优先创建 4 个画板，而不是一上来做完整高保真组件库：

1. `Workbench / Empty`
2. `Workbench / Files Selected`
3. `Workbench / Running`
4. `TaskCenter / Completed Task`

每个画板只验证一个核心问题：

- Empty：用户是否知道第一步该添加音频。
- Files Selected：用户是否知道配置是否正确、哪里执行。
- Running：用户是否知道任务跑到哪一步。
- Completed：用户是否能直接拿到结果。

## 8. 实施顺序

建议分 4 步推进。

### Step 1：恢复可读性

- 修复 `desktop/src/pages/Workbench.tsx` 和 `TaskCenter.tsx` 中的中文乱码。
- 梳理按钮文案和字段命名。
- 暂不大改布局。

验收标准：用户能读懂页面上每个按钮、字段、状态。

### Step 2：建立新视觉 token

- 在 `desktop/src/index.css` 中替换 neumorphism token。
- 建立背景、面板、边框、主色、语义色、字体、间距、圆角规则。
- 保留旧组件 API，先减少迁移风险。

验收标准：页面从灰色软卡片变成清晰、专业、可扫读的生产工具界面。

### Step 3：重构 Workbench

- 将主按钮移到顶部任务带。
- 将文件队列和流水线阶段作为主内容。
- 将高级参数降级到折叠/抽屉。
- 增加右侧参数摘要。

验收标准：用户从上到下自然完成“添加音频 -> 选择预设 -> 确认流程 -> 执行”。

### Step 4：重构 TaskCenter

- 任务卡片突出当前阶段和产物操作。
- 右侧改为任务详情，不再默认只是日志面板。
- 日志降级为详情中的排障工具。

验收标准：用户能快速判断任务状态，并在完成后直接找到结果。

## 9. 暂不建议做的事

- 暂不改旧 GUI。
- 暂不先做复杂动画。
- 暂不引入大型 UI 框架。
- 暂不做完整 Figma 组件库。
- 暂不把所有后端任务 API 问题和 UI 改版绑死。

原因：当前最大收益来自信息架构和可读性，不是技术栈升级。

## 10. 下一步建议

建议立即进入 Step 1 和 Step 2：

1. 先修正文案乱码，保证页面可读。
2. 再替换视觉 token，让现有页面立刻从 Demo 感转向工具感。
3. 然后再动 Workbench 布局。

这样风险最低，也最容易每一步都看到效果。
