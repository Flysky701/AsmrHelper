# 台本转字幕工作区 v2：实现方案

状态：设计草案，尚未实现。用户已认可操作顺序；本文件提出具体技术方案，默认行为仍可调整。

## 1. 产品目标与范围

操作路径：导入整套素材 → 确认章节配对 → 生成字幕 → 试听和处理疑点 → 按音频导出。

以录音实际内容和顺序为准，台本用于提供准确文字。保留未匹配台词和录音额外内容，供用户确认；模型无法确认“演员未读”，只能标记“未找到匹配”。

首版支持一份 PDF/TXT 台本、多章节、多音频，每个处理单元绑定一个章节与一个音频范围。整段音频是默认范围；通过手动拆分章节或范围表达更复杂配对。工作区可以仅整理文本，不强制运行 ASR。

首版包括章节调整、匹配疑点、字幕文字及边界编辑、局部重跑、重新打开继续处理。完整波形编辑、多说话人自动分离、OCR、翻译和配音暂不作为本模块首版内容。普通音频播放、区间试听和数值边界编辑足以支持第一轮使用。

## 2. 已有实现与复用边界

以下为检查源码所得事实：

- `core/tasks` 有 TaskSpec、执行器注册、协作取消；新任务类型需要加入注册列表并绑定执行器。
- `app/persistence/state_store.py` 使用 SQLite 存任务和产物索引；现有表没有台本工作区数据。
- `core/engines/asr/registry.py` 提供多 ASR 引擎注册；新流程不写死 Faster-Whisper。
- `core/engines/alignment.py` 有独立强制对齐和带锚点音频切片；尚未接入旧台本流程。
- `core/subtitles/exporter.py` 有统一导出；导出入口含归一化，可能修正非法时间，因此新模块必须先严格校验，不能以归一化代替检查。
- `SubtitleWorkshop.tsx` 已有字幕编辑和播放器定位，但没有本方案的工作区、版本和匹配关系。
- `InputCatalog` 的 ID 在内存递增，不能直接作为持久工作区唯一标识。

重写旧台本流水线、LLM 匹配与时间补全。复用任务、Provider、资源检查、音频解码、独立对齐、统一导出和播放器；通过适配器衔接，不复制通用实现。

## 3. 数据结构

所有实体使用稳定 UUID；排序使用独立字段，不能拿列表索引充当身份。时间统一为相对原始音频的秒；切片内部时间必须经过显式偏移转换。

| 对象 | 主要字段与责任 |
| --- | --- |
| ScriptProject | id、name、schema_version、revision、当前文档版本、配置、创建和更新时间 |
| SourceAsset | id、绝对路径、文件大小、mtime、内容指纹、类型、音频时长和采样信息；原文件只读 |
| SourceBlock | id、asset_id、page、bbox/文本偏移、原始文字、阅读顺序、正文/批注来源 |
| ScriptSection | id、title、order、source_block_ids、拆分或合并来源 |
| ScriptUtterance | id、section_id、speaker、raw_text、edited_text、source_refs、kind、included、revision |
| TrackBinding | id、section_id、audio_asset_id、range_start/end、已有字幕来源、状态 |
| AsrSegment | id、binding_id、start/end、text、可选 words、引擎与模型版本、运行来源 |
| MatchGroup | id、utterance_ids、asr_segment_ids、匹配状态、候选依据、文字版本、可选人工音频范围 |
| AlignmentResult | match_group_id、words、片段时间、时间来源、警告、运行版本 |
| SubtitleCue | id、binding_id、text、speaker、start/end、source_refs、match_group_ids、人工锁定字段 |
| ReviewIssue | id、对象引用、类型、严重度、处理状态、原因、对应输入版本 |
| StageRun | task_id、阶段、处理范围、输入摘要、配置摘要、引擎版本、输出引用、状态 |

台词、匹配组、字幕条目分开建模，允许一对多、多对一。未匹配台词没有时间，不能直接变成正式 SubtitleCue。角色来自台本，仅是文本归属，不等于已经识别出录音中的说话人。

匹配状态：matched / ambiguous / unmatched_script / extra_audio / manual。时间来源：asr / forced_alignment / manual。问题处理：open / resolved / accepted；忽略某句必须记录用户选择，不能直接删除原句。

## 4. 持久化与版本

沿用本地 SQLite 基础设施，新增专用 repository 与迁移，不把工作区正文塞进 TaskSpec。

首版表：script_projects（元信息及当前 revision）、script_project_revisions（不可变结构化 JSON 快照）、script_stage_runs（任务和阶段输入输出索引）。每次编辑通过事务写入新快照并推进当前 revision，API 要求 expected_revision，冲突返回 409。先使用快照降低关系维护成本，后续有性能证据再拆分行级表。

较大的 ASR/对齐 JSON、播放派生文件存至输出根目录 `script-projects/<project_id>/runs/<run_id>/`，文件不可变。先写临时文件并原子替换，再提交数据库索引；中断造成的孤立文件不作为有效结果。正式产物登记到已有 Artifact 服务。

原始音频和 PDF 默认引用，不复制或改写。重新打开检查路径和指纹；文件丢失允许重新定位，内容改变时要求重新导入对应资产版本。项目资产 ID 独立于 InputCatalog 的临时 ID。

任务读取冻结的输入 revision。完成时若相关依赖已被用户修改，结果保存为历史候选并标记过期，不能覆盖当前编辑。其他章节的无关修改不必使当前章节任务失效，以处理范围依赖摘要判断。

## 5. 处理阶段

### 5.1 导入、解析、章节配对

PDF 优先按文字坐标恢复阅读顺序、角色段落和章节，而不是把“提取到非空文本”当成成功。采用 pdfplumber 获取文字块；pypdf 可提供元信息和对照结果。批注作为独立来源，不并入正文。没有文字层时提示需要 OCR，不生成空白字幕。

匹配副本进行 Unicode 规范化、全半角统一、空白处理，原文保持原样。章标题支持 Track、トラック、全角数字及装饰分隔线，必须结合块位置判断，避免把对白中出现的词当章节。

从文件名 Track 编号推荐章节配对。编号缺失、冲突、重复音频或范围不确定时显示待处理，用户可调整。台本角色标记结合布局提取，演出说明先分类，保留可恢复来源。未知文字保留并提示。

可选 LLM 清洗返回按稳定 ID 标注的分类或修改建议；程序校验覆盖率与引用，接受后形成新版本。分块上下文不计入当前批输出，避免重复拼接。基础解析与章节配对不依赖 LLM 可用。

### 5.2 获取时间锚点

使用已有 ASR 注册机制和统一运行时；配置保存 provider、model、language 及影响结果的参数。短而准确的纯台词可提供直接强制对齐路径，但默认长录音走 ASR 锚点。

已有字幕先检查语种、时间范围、异常重复、文字覆盖情况；时间合法不代表与音频匹配。不可信字幕只能作为参考，不能自动成为唯一锚点。没有音频时只提供文本匹配和沿用已有时间，并标记“未经声学校准”。

音频保持原时间坐标；不得无记录删除静音。解码派生文件保留时长、采样率和偏移映射。双声道保留原文件用于试听，对识别或对齐的混音策略由适配器明确记录。双声道不等于两个独立说话人。

### 5.3 内容匹配

采用分层匹配，先建立明显锚点，再解决锚点之间的局部区间：

1. 按章节限制候选；文本规范化后按字符片段相似度找较长、区分度高的候选。
2. 选取顺序一致的高可信锚点链，重复短句不能独立成为强锚点。
3. 锚点之间做带跳过代价的序列动态规划。初始允许 1:1、1:2、2:1、1:3、3:1 组合及任一侧跳过；最大组合规模是可调参数，不代表已找到最佳值。
4. 评分考虑文字相似、相邻一致性、跨度和最佳/次佳候选差距。保留分项依据，不把启发式分数显示为“准确率”。
5. 模糊区间可调用 LLM，提供上下文和候选 ID，仅返回匹配组或 abstain。禁止返回时间戳。校验 ID、范围、重复占用、覆盖与顺序；不通过则保留疑点。
6. 找不到可靠锚点的区间留待人工指定范围。局部倒序可作为建议显示，首版不自动处理全局重排。

同一 ASR 片段被多句共享必须表达为一个多对一匹配组；不能被互不相关的组重复消费。ASR 额外内容保留识别文字并标记待确认。台本与录音词句有实质差异时提供候选修订，不直接用台本覆盖所有识别文本。

### 5.4 声学强制对齐

输入已确认的匹配组文字及锚点音频范围。复用 AlignmentRuntime，通过适配器完成格式和运行时转换。

当前实现读取 soundfile 可读音频、每窗最长 300 秒且有两侧余量。适配器必须核对解码格式、含余量的窗口时长，以及实际采样起点；窗口超限应依据可靠 ASR 边界和匹配关系拆分。无法确定文字拆分点时进入待处理，禁止按字数平均分配。

匹配组为最小持久化单元，逐组或有上限的小批调用；每批前后检查取消，防止当前运行时一次处理所有窗口导致长时间不能取消。ASR 与对齐模型阶段切换时协调 GPU 资源，初期 GPU 任务串行。

校验有限数、非负、起止关系、音频界限、文字覆盖和异常时长。模型可能规范化文字，需显式词字符映射，映射失败则保留组级范围并提示，不擅自将词时间贴到错误文字上。

局部失败保留真实 ASR 范围并记录“未校准”；无可靠时间则不产生可导出条目。整个模型不可用时可生成 ASR 时间草稿并显式说明跳过阶段，不能将配置为强制要求的阶段假装执行成功。

### 5.5 字幕组织与检查

按照对齐后的词句、标点、停顿与可读性拆并字幕；不能把 PDF 一行固定当一条字幕。没有词级时间时保留整个匹配组，不按字数推算拆句时间。长度和阅读速度先作为可调整提示，具体默认值用样本试跑后确定。

保留语气词和实际发声内容；声效提示可选，演出指令不默认显示。角色可保留在内部，导出时选择是否显示。

硬错误：非法数字、倒置、越界、缺时间。疑点：异常长、重复占用、覆盖缺口和重叠。双角色真实重叠允许人工确认，不能一律平移成不重叠；首版在合并显示与保留重叠之间提供明确操作，不承诺自动分离双人对白。

## 6. 后台任务、取消与恢复

建议新增任务类型 script.import、script.generate、script.reprocess、script.export，复用 TaskDispatcher、任务状态和 Artifact。

导入是一个任务；生成按 TrackBinding 创建任务，前端一次提交多个处理单元，后端返回 task_ids。工作区聚合展示进度，任务中心展示执行详情并能返回对应工作区。业务上的“待校对”独立于任务 completed/failed 状态。

在 PDF 页、LLM 请求、ASR 可用回调、对齐组之间检查取消。请求设置超时与有限重试；无法中止的单次推理显示“正在取消，等待当前调用结束”，不承诺即时释放。

阶段输出以输入摘要和配置摘要定位。失败重试创建新 Task，复用已完成且依赖一致的阶段。中途退出将运行记录标为 interrupted，重新打开可恢复；首版只保证已落盘阶段或组的复用，不承诺任意 ASR 推理进度恢复。

输入变更影响：

| 修改 | 重算范围 |
| --- | --- |
| 配对音频或音频范围 | 对应处理单元的 ASR、匹配、对齐、字幕 |
| 台词内容或章节边界 | 相关匹配区间和下游，保留原音频 ASR |
| 人工指定匹配范围 | 当前组对齐和下游 |
| 手动字幕显示文字 | 当前字幕检查；提示文字与对齐依据可能不同，不自动重跑 |
| 手动字幕时间 | 当前字幕检查和导出 |
| 字幕分句配置 | 字幕组织及检查，保留上游 |
| LLM 配置 | 仅依赖它的清洗/匹配阶段及下游 |

局部重跑取最近可靠锚点之间的区间，并纳入跨边界匹配组。受影响的人工锁定内容不能静默覆盖，结果作为候选供应用；无锁定字段才自动更新。问题清单随新版本重新计算，旧版本已解决问题不能掩盖新问题。

## 7. API 草案

以下为拟新增接口，统一位于 `/api/v1/script-projects`。

| 接口 | 责任 |
| --- | --- |
| POST / | 创建空工作区，返回 project_id/revision |
| GET /，GET /{id} | 最近工作区、工作区元信息与章节摘要 |
| POST /{id}/imports | 导入文件或受控目录扫描，返回导入 task_id |
| GET /{id}/sections/{section_id} | 获取分页台词、来源和章节详情 |
| PATCH /{id} | 带 expected_revision 的类型化编辑：配对、台词、章节拆并等 |
| POST /{id}/runs | 冻结当前版本，选择 bindings 和配置，创建生成任务 |
| GET /{id}/bindings/{binding_id}/review | 分页字幕、匹配组、问题及运行摘要 |
| PATCH /{id}/bindings/{binding_id}/review | 批量编辑字幕、人工匹配、锁定及问题处理 |
| POST /{id}/reprocess | 指定组/区间和起始阶段，创建局部重跑任务 |
| POST /{id}/exports | 固定版本、选择 tracks/格式/目录，创建导出任务 |

继续使用已有任务查询与取消接口。所有变更及运行请求返回明确 revision；创建任务附 request_id 防止重复提交。PATCH 采用明确操作类型而非任意内部 JSON 覆盖，并校验所有引用属于当前项目。

## 8. 页面组织

保留字幕工坊作为入口，台本页替换为工作区列表和工作区详情。创建后保持在工作区内，不强制跳到任务中心。

- 整理素材：文件列表、章节与音频配对、章节源文预览；页面/文本块边界拆分，角色台词可修订。
- 生成：按 Track 选择运行，显示解析/识别/匹配/对齐/整理进度和问题数量；高级参数默认折叠。
- 校对：左侧章节与问题筛选，中间虚拟化字幕列表，右侧原文与匹配依据，底部播放器与区间编辑。
- 导出：格式、目录、文件名、角色显示选项、每个 Track 的待处理项摘要。

运行中可编辑，但受影响结果按版本规则处理。保存采用后端持久化、前端防抖批量提交；启动任务/导出前必须提交未保存编辑。冲突提示刷新或比较，不直接覆盖。

复用现有播放器，新增 playRange(start,end) 行为及跨音频切换完成后定位，结束自动暂停。播放原音频并保留双声道。波形可后续增加，但数值边界、键盘微调和区间试听属于首版。

正式导出要求硬错误已处理，未匹配项有明确处置；允许单独导出有有效时间的草稿，同时保存排除项和疑点报告，不丢弃工作区原始记录。文件名默认跟随音频，已有文件自动生成版本名，避免覆盖。每个文件通过校验后原子写入并登记 Artifact；部分 Track 失败不撤销其他已完成文件。

## 9. 代码划分建议

新增 `src/core/script_subtitles/`：models、parser、cleaner、matcher、aligner_adapter、composer、validator、invalidation。纯领域逻辑与模型调用接口分离，方便离线测试。

新增 `src/app/services/script_project_service.py` 负责编辑与持久化，`script_project_executor.py` 负责任务编排；`src/app/persistence/script_project_store.py` 负责迁移、快照与运行记录。新增 HTTP schemas/routes 与桌面 API/types。

桌面 `pages/subtitle-workshop/script-project/` 拆分 ProjectList、SourceMapping、ScriptReview、GenerationPanel、CueReview、ExportPanel。只持有界面临时状态，后端工作区是事实来源。

不直接调用旧 ScriptToSubtitlePipeline；共享功能经小适配器复用，避免把旧回退逻辑带入新流程。

## 10. 实施顺序与可见产出

1. 数据与导入：版本存储、文件检查、PDF 结构恢复、章节映射页。可打开样本并看到五个正确章节及对应音频，关闭后继续编辑。
2. 生成与校对骨架：ASR、确定性匹配、粗时间草稿、未匹配清单、播放器区间试听。此阶段明确显示时间未经精校。
3. 匹配和声学对齐：局部 LLM、强制对齐适配、字幕组织、问题分类。验证单 Track，再运行五 Track。
4. 完整编辑闭环：局部重跑、锁定保护、版本冲突、中断恢复、导出和旧入口替换。

每步是内部可运行增量；完整首版包含四步，不把只生成草稿视为重写完成。新模块稳定前保留旧接口供历史调用，新页面使用新接口。旧 Task/Artifact 不迁成虚假的工作区；旧字幕只能作为用户导入的参考。确认调用方迁移后再移除旧执行代码，保留历史任务查询。

## 11. 样本如何帮助设计

RJ01519686 的事实：38 页正文、五章节、五段双声道音频约 46:43；批注版正文提取一致，现有解析只识别一个章节；已有 VTT 的 187 条只使用 13 组时间范围。已有 VTT 用于问题检测回归，不作为正确时间基准。尚未核实真实录音台词一致性。

先用它决定哪些人工修订操作实际需要，再调整算法阈值。首轮无需预先承诺准确率：查看能否顺利配对、能否定位疑点、能否修正并继续。技术测试覆盖 ID/版本一致性、章节拆分、批注隔离、多对多映射、重复句、空 ASR、非法 LLM、时间单位及偏移、合法重叠、取消、恢复和导出往返。

素材保持在用户目录，不提交到仓库，不自动上传。算法回归使用合成片段；真实 ASR/LLM 的效果和耗时在后续明确试跑中记录。
